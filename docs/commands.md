# Command reference

Every script under `scripts/` and `ps/scripts/`, from its own header. In a repository that
vendors script-helpers, the paths start with `scripts/script-helpers/`.
Most scripts print the same text with `-h` or `--help`.

This page is generated by `scripts/gen_command_reference.py`; edit the
script header, then run it. The library's functions are in the
[API index](api.md).

## Git hooks and setup

### `scripts/foxguard_report.sh`

Scan files with foxguard and write the findings as formatted JSON, to keep as evidence or compare later.

```text
Usage: bash scripts/foxguard_report.sh [--base <ref>] [--output <file>] [--] [<path>...]
  --base <ref>     Scan the files changed between <ref> and HEAD (the pre-push
                   hook prints this with the remote's commit). Default when no
                   paths are given: the upstream branch, else origin/HEAD.
  --output <file>  Where to write the JSON (default: foxguard-report.json).
  <path>...        Scan these files instead of a range.
```

Exit codes:

```text
0  No findings.
1  Findings (written to the file).
2  Usage or git error, the report could not be written, or a file could not
be scanned (listed under "errors").
3  foxguard not installed and not installable here.
```

Example:

```text
  bash scripts/script-helpers/scripts/foxguard_report.sh --base origin/main --output foxguard-report.json
```

### `scripts/owner_scope.sh`

Decide whether a repository belongs to a configured owner, failing closed. Sourced by the global hooks and the Claude Code hook.

```text
Usage: source scripts/owner_scope.sh; scope_owners; scope_owner_of <url>; scope_in_scope <owners> [url...]
  SCRIPT_HELPERS_OWNERS  Comma-separated GitHub users/orgs. Default:
                         git config --global script-helpers.owners.
  -h, --help             Executed directly: show this help.
```

Exit codes:

```text
scope_owners returns 0 (owners printed, or none set) or 2 (git config unreadable).
scope_owner_of returns 0 with the owner printed, 1 for a non-github URL.
scope_in_scope returns 0 in scope, 1 out of scope.
scope_repo_urls returns 0, or 2 when git cannot list the remotes.
Executed directly: 0 for -h/--help, 2 otherwise (the file must be sourced).
```

Example:

```text
  source scripts/owner_scope.sh
  scope_in_scope "$(scope_owners)" "$(git remote get-url origin)" && echo checked
```

### `scripts/push_checks.sh`

Sourced by the pre-push hook and the hook dispatcher: hygiene and lint of what a push changes; blocks on any finding.

```text
Usage: source scripts/push_checks.sh; push_checks <refs-file> <remote-name> [<url>]
  <refs-file>    The ref lines git gave pre-push, saved to a file.
  <remote-name>  git's first pre-push argument.
  <url>          git's second pre-push argument.
  -h, --help     Executed directly: show this help.
```

Exit codes:

```text
push_checks returns 0 when the push is clean and 1 on any finding (each
finding on stderr); push_tests returns 1 when tests fail or none are found.
Executed directly: 0 for -h/--help, 2 otherwise (the file must be sourced).
```

Example:

```text
  source scripts/push_checks.sh
  push_checks "$refs" origin git@github.com:owner/repo.git
```

Exit codes:


### `scripts/security_hooks.sh`

The security steps every git hook runs, sourced by scripts/git-hooks/* and the global dispatcher.

```text
Usage: source scripts/security_hooks.sh; sec_pre_push <refs-file> <remote-name> <url> | sec_pre_commit | sec_commit_msg <msg-file>
  SCRIPT_HELPERS_SECURITY_DIR  Directory holding check_private_names.sh and
                               check_sensitive.sh. Set by the global hooks;
                               otherwise they are looked up in the repository.
  SECURITY_GATE_ALLOW_UNCHECKED=1  Let a push through when a check could not
                               run (exit 2, script missing, scope unknown), with
                               a warning. Narrow on purpose: --no-verify skips
                               every check, this skips none that can run.
                               SENSITIVE_ALLOW_UNCHECKED=1 is the same.
  FOXGUARD_CMD                 foxguard command to run (default: the pinned
                               binary in the cache, else foxguard on PATH).
```

Exit codes:

```text
Sourced: no output, no exit. Each sec_* function returns 0 to let the
commit or push continue and 1 to refuse; sec_find returns 127 when a
check script is missing.
Executed: 0 for -h/--help; 2 for anything else (it must be sourced).
```

Example:

```text
source scripts/security_hooks.sh && sec_pre_push "$refs_file" origin "$url" || exit 1
```

### `scripts/setup-hooks.sh`

Configure git to use shared or repository-local hook scripts, and install the Claude Code security hook.

```text
Usage: bash scripts/setup-hooks.sh [--claude-repo|--agent-repo <list>|--global|--claude|--agent <list>|--all|--managed] [--uninstall] | --repair | --status [--porcelain] | --doctor | --install-gitleaks | --install-foxguard
  (none)        Set up this repository. With no hooks running here yet, point its
                core.hooksPath at the shared hooks. If hooks already run (a local or
                global core.hooksPath set by another tool, or .git/hooks), keep them:
                save the old value in .git/config and chain, in order, the security
                checks (owners' repositories only), this repository's committed
                hooks, then the hooks that ran before. Only untracked files change.
                --uninstall alone undoes it and restores the previous value.
  --global      Install the git hooks machine-wide: copy them, with their own copy of
                the check scripts, to <data>/script-helpers/git-hooks and set the
                GLOBAL core.hooksPath there, after printing the old value and saving it.
  --claude      Install the Claude Code PreToolUse hook for this user: copy it to
                <data>/script-helpers/claude-hooks and add one entry to
                ${CLAUDE_CONFIG_DIR:-~/.claude}/settings.json (matcher Bash, timeout
                60 s, shell bash). Every other key and hook in the file is kept; an
                older entry for the same hook is replaced; a backup is written first.
  --claude-repo Install the Claude Code hook for this repository only: one entry in
                .claude/settings.local.json, listed in .git/info/exclude so it is never
                committed; backups go under .git/script-helpers/. With --uninstall:
                remove it, and the file too when this script created it.
  --agent-repo <list>  The same check for other AI agents, this repository only.
                <list>: codex, gemini, copilot, cursor, comma-separated, or all.
                Writes our entry into the agent's project hook file, listed in
                .git/info/exclude so it is never committed; other entries stay:
                  codex    .codex/hooks.json            (PreToolUse, matcher Bash)
                  gemini   .gemini/settings.json        (BeforeTool, run_shell_command)
                  copilot  .github/hooks/script-helpers.json (preToolUse, bash|powershell)
                  cursor   .cursor/hooks.json           (beforeShellExecution, failClosed)
                Each runs scripts/agent-hooks/agent_hook.sh <agent> from a copy in
                <data>/script-helpers/agent-repo-hooks. Codex and Gemini ask you to
                trust a project hook before it runs (Codex: /hooks). With
                --uninstall: remove our entry, and the file when this script made it.
  --agent <list>  The same for this user: ~/.codex/hooks.json, ~/.gemini/settings.json,
                ${COPILOT_HOME:-~/.copilot}/hooks/script-helpers.json, ~/.cursor/hooks.json;
                copy in <data>/script-helpers/agent-hooks.
  --all         --global and --claude.
  --managed     Install the Claude hook into the OS managed settings file instead,
                which no user or project setting can turn off. Needs admin rights;
                refuses (exit 2) without write access, and never runs sudo itself.
                  Linux    /etc/claude-code/managed-settings.json
                  macOS    /Library/Application Support/ClaudeCode/managed-settings.json
                  Windows  C:\Program Files\ClaudeCode\managed-settings.json
                The hook copy goes to script-helpers/ next to that file.
  --uninstall   With --global, --claude, --all or --managed: undo that install.
                Other settings and hooks are left as they are.
  --repair      In this repository: if another tool replaced core.hooksPath after
                the setup here (husky does on npm install), chain again: the new
                value becomes the previous one, so its hooks and ours both run. The
                value it replaced is kept as script-helpers.previous-hooksPath-history.
                Also chains a direct setup that runs the repository's own hooks
                without the current security checks (unscanned=yes below).
                Also sets up again a setup whose hooks directory is gone (broken=yes).
                Nothing to repair: exit 0. Not set up here: exit 1.
  --status      Show what is installed, and the prerequisites.
  --porcelain   With --status, in a repository: one line of tab-separated key=value
                fields for scripts: mode (chained, direct, none), taken_over (yes,
                no), core_hooksPath, expected, previous, target, claude_repo (yes,
                no), global (yes when the --global hooks run here), agents (the
                other agents with our hook here, comma-separated), unscanned (yes when
                a direct setup points at hooks other than this copy's own, such as
                an older vendored script-helpers or .githooks, so the current
                security checks do not run; --repair chains them), broken (yes when
                core.hooksPath names a missing directory, or our setup's has no
                pre-push, so no push checks run; --repair sets it up again).
                With --claude, anywhere: claude_user (ok; absent; unknown: no
                Python to read the settings; broken: the script it runs is
                missing; stale: it runs a file outside the installed copy, such
                as a checkout), hook, installed (version).
  --doctor      The prerequisites, then four probes through the installed Claude
                hook, from a throwaway repository under the first owner: a private
                name from your list, an SSN-shaped number, and git push --no-verify
                (each must be refused for that reason, with the deny decision on
                stdout), and ls (must pass), with the time each took. A refusal for
                another reason (no name list, no gitleaks) is a failure. Exit 1 on
                any failure.
  --install-gitleaks  Download the pinned gitleaks (SHA-256 checked) into the cache.
  --install-foxguard  Download the pinned foxguard (SHA-256 checked) into the cache.
  Every install offers both (asked on a terminal, printed otherwise); a push
  with one missing installs it (not in CI, nor with
  SCRIPT_HELPERS_NO_AUTO_INSTALL=1), and says what did not run when it cannot.
  <data> is %LOCALAPPDATA% on Windows (Git Bash), else ${XDG_DATA_HOME:-~/.local/share}.
  Installing refuses (exit 2) until owners are configured:
    git config --global script-helpers.owners <user-or-org>[,<another>]
  Only those owners' github.com repositories are checked; every other repository
  runs only its own hooks. See docs/security-gates.md.
  Hook directory priority (no option):
    1. .githooks/  (repo-local overrides with both pre-commit and pre-push)
    2. git-hooks/ next to this script: the hooks bundled with this copy of
       script-helpers, wherever it is vendored (scripts/script-helpers,
       vendor/script-helpers, ...) or script-helpers' own scripts/git-hooks
    3. scripts/script-helpers/scripts/git-hooks/, then scripts/git-hooks/
  Only this copy's own bundled hooks are used directly. Any other hooks
  directory (.githooks, an older vendored script-helpers) runs chained after
  the current security checks, so a clone is never only as safe as its copy.
  The shared pre-push hands over to .githooks/pre-push when a repository has
  one (for example the protected-refs guard), so a repository with only
  .githooks/pre-push gets the shared hooks and still runs its own.
  The pre-push hook blocks on security, hygiene and lint of the changed files
  (scripts/push_checks.sh); it runs no tests (make test or ./dev test)
  unless the repository opts in: git config script-helpers.push-tests quick. git
  holds the push's connection open meanwhile. Over SSH a long run (a first or
  very large push) is cut off (exit 141) unless a
  keepalive is set: ~/.ssh/config "Host github.com" + "ServerAliveInterval 20"
  (every repository), git config core.sshCommand "ssh -o ServerAliveInterval=20"
  (one repository), or GIT_SSH_COMMAND="ssh -o ServerAliveInterval=20" git push
  (one push). HTTPS remotes are not affected. The hook and --status say so.
```

Exit codes:

```text
0  done
1  failed (or a --doctor probe failed)
2  refused: no owners, no Python 3, no write access, bad arguments
3  a settings/hooks JSON file is not valid JSON; with --install-gitleaks or
--install-foxguard: no release binary for this platform, or curl/wget or
a SHA-256 tool is missing
```

Example:

```text
bash scripts/setup-hooks.sh --status
```

### `scripts/check_sensitive.sh`

Fail when text about to be published carries a credential, a personal identifier or PII.

```text
Usage: scripts/check_sensitive.sh [--push-refs <file>|--range <revs>|--staged|--file <path>|--stdin] [--repo <path>] [--no-gitleaks] [--no-machine] [--no-inline-allow] [--terms <path>] [--refresh-public-ip] [--list-identifiers] [-h]
  --push-refs <file>  The ref lines git gives a pre-push hook on stdin, saved to a file.
                      Checks every commit in the push that the target lacks (--remote).
  --range <revs>      Commits to check, as git log arguments, e.g. origin/main..HEAD.
  --staged            The staged changes (pre-commit).
  --file <path>       A file, all of it: a commit message, a PR or issue body. Repeatable.
  --stdin             Standard input, all of it.
  --remote <name>     With --push-refs: the remote pushed to (git's first pre-push
                      argument). A new branch is checked against that remote's refs
                      only; without it, or for a bare URL, its whole history.
  --repo <path>       Repository (default: cwd).
  --no-gitleaks       Skip the credential scan. It then reports nothing about credentials.
  --no-machine        Skip this machine's live identifiers (addresses, hostname, home path).
  --terms <path>      Personal terms file. Default: SENSITIVE_TERMS_FILE, else
                      ${XDG_CONFIG_HOME:-~/.config}/script-helpers/sensitive-terms.txt

                      The only network call this script makes; never run implicitly.
```

### `scripts/signing_secrets.sh`

Set the package-signing secrets and variables (the names in ci-helpers docs/packaging.md) on a list of GitHub repositories, or check which repositories miss which name. Values go to gh on stdin, never on a command line, and are never printed.

```text
Usage: ./signing_secrets.sh --repos <owner/a,owner/b> --group <gpg|apple> [--group ...] [options] [--check|--dry-run]
  --repos <list>            Comma-separated owner/name list (required).
  --group <gpg|apple>       Names to set or check; repeat for both (required).
  --gpg-key <fingerprint>   gpg: key to export (40 hex characters).
                            Passphrase: GPG_PASSPHRASE env, else prompted.
  --ppa <owner/name=ppa:id/name>
                            gpg: set PPA_TARGET on that repository; repeat.
  --launchpad-ssh-key <file>
                            gpg: set LAUNCHPAD_SSH_PRIVATE_KEY (sftp only).
  --apple-p12 <file>        apple: Developer ID Application .p12.
  --apple-identity <text>   apple: "Developer ID Application: Name (TEAMID)".
  --apple-team <id>         apple: 10-character team ID.
  --apple-id <email>        apple: Apple ID for notarization.
                            Passwords: APPLE_CERTIFICATE_PASSWORD and
                            APPLE_APP_PASSWORD env, else prompted.
                            The .p12 must open with its password and hold
                            the --apple-identity certificate, in date, and
                            its private key (openssl). Warns when the
                            certificate expires within 30 days.
  --skip-p12-check          apple: store the .p12 without opening it
                            (where openssl is not installed).
  --check                   Report missing names per repository; exit 1 if any.
  --dry-run                 Print the names that would be set; set nothing.
  -h, --help                Show help.
```

Exit codes:

```text
0  Every name was set, or --check found every name on every repository.
1  --check found a missing name or could not list a repository, or gh
could not set a name.
2  Bad arguments, a missing tool (gh, gpg, openssl), a key not in the
keyring, a passphrase that does not unlock it, an --apple-identity
that does not end in the --apple-team, a .p12 that does not open with
APPLE_CERTIFICATE_PASSWORD, lacks the --apple-identity certificate or
its private key, or holds it expired, or an empty value; nothing was
set.
130, 143  Interrupted (INT, TERM); the scratch directory is removed.
```

Example:

```text
  ./signing_secrets.sh --repos me/tool --group gpg --gpg-key <FPR> --ppa me/tool=ppa:me/tool
  ./signing_secrets.sh --repos me/a,me/b --group gpg --group apple --check
```
